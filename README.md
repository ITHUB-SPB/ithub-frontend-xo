# КТ#2 "Крестики-Нолики"

Приложение представляет игру в крестики-нолики с хранением состояния в локальном хранилище.

Реализуется с использованием фреймворка `React 19`, сборщика `Vite 8`, типизацией на `TypeScript 7`. Приложение должно быть реализовано без дополнительных библиотек. Можно использовать `useState`, `useReducer`, `useEffect`, `useLayoutEffect`, `useMemo`, `useCallback`, `Context API`.

Базовый дизайн уже реализован. Для вдохновения можете пользоваться [этим](https://www.figma.com/design/1rKJjzNZJ7BL06XaFqk8Xj/Tic-Tac-Toe--Community-?node-id=0-1&p=f&t=2bQ6SV4kGJmD35Qa-0) либо любыми иными макетами.

## Игровой флоу

Приложение состоит из следующих экранов:

1. Экран с фоновой заставкой (сплэш-скрин);
2. Экран выбора настроек игроков c полями ввода и кнопкой "Начать";
3. Экран игры с игровым полем, легендой и кнопкой "Начать заново";
4. Экран результатов с информацией о результатах и кнопкой "Начать заново".

### 1. Экран с фоновой заставкой (сплэш-скрин)

При запуске отображается **экран 1**, происходит проверка `localStorage` на наличие информации о незавершенных играх. Если незавершенных игр нет - ожидаем нажатия на блок с названием, по нажатию переводим на **экран 2**. Если найдена незавершенная игра, на том же экране появляется диалоговая форма с выбором: продолжить игру либо начать новую игру. При продолжении происходит переход к **экрану 3**, в случае новой игры - сброс сохраненной информации об игре и переход к **экрану 2**.

### 2. Экран выбора настроек игроков c полями ввода и кнопкой "Начать"

На **экране 2** представлены поля ввода для имён игроков, играющих за крестики и за нолики, а также (на выбор) выбор цветов либо эмодзи игроков. В случае, если в `localStorage` уже есть информация об игроках, нужно отобразить эти данные в качестве стартовых, но позволить при желании их изменить. По нажатию на кнопку "Начать" данные об игроках необходимо сохранить в `localStorage`.

### 3. Экран игры с игровым полем, легендой и кнопкой "Начать заново"

На **экране 3** представлены игровая доска, легенда с информацией об игроках и очереди хода и кнопка "Начать заново". Игроки делают ходы по очереди (начинают всегда крестики). Поле с именем игрока, чей ход ожидается в данный момент, отображается нормально, поле второго игрока - со сниженной насыщенностью.

По нажатию на кнопку "Начать заново" отображается диалоговая форма для подтверждение действия: в случае подтверждения происходит сброс состояния игры в `localStorage` и возвращение к **экрану 2**, в случае отмены игра продолжается.

После каждого хода проверяется статус игры: завершена ли она победой одного из игроков или же ничьей. В случае, если игра завершена, происходит переход на **экран 4**.

### 4. Экран результатов с информацией о результатах и кнопкой "Новая игра"

Если один из игроков получил три-в-ряд, его победные ячейки подсвечиваются зеленым (либо фирменным цветом игрока), также на экране отображается сообщение о победителе. При ничьей подсветки не происходит.

Независимо от результата игры также отображается кнопка "Начать заново", при нажатии на которую состояние игры сбрасывается и происходит переход на **экран 2**.

### Компоненты

При реализации придерживайтесь следующей структуры компонентов:

- сплэш-скрин
  - векторные иконки
  - основная надпись
- экран настройки
  - блок настройки игрока
  - кнопка "начать"
- экран игры
  - легенда
    - информация об игроке
  - игровое поле
    - ячейка игрового поля
  - кнопка "начать снова"
- экран результатов
  - игровое поле
  - информация о результате
  - кнопка "начать снова"

Если компоненты можно переиспользовать, старайтесь это делать.

### Стейт

#### Стейт приложения (глобальный)

Приложение может находиться в одном из следующих состояний:

- **idle**, стартовый этап, соответствует **экрану 1**,
- **settings**, этап настройки игроков, соответствует **экрану 2**,
- **progress**, этап игры, соответствует **экрану 3**,
- **results**, этап результатов, соответствует **экрану 4**.

Читайте глобальное состояние в компоненте `App` для определения экрана, который нужно показать в данный момент. Изменяйте глобальное состояние, если необходимо перевести пользователя к другому экрану.

Для управления глобальным состоянием можете использовать `State API` либо `Context API`.

#### Стейт игры

Состояние игры включает в себя:

- состояние поля,
- состояние статуса.

Для управления состоянием игры рекомендуется использовать `Reducer API` либо `State API`.

##### Состояние поля

В исходном виде имеет вид массива состояний ячеек: двумерного...

```ts
[
  [null, null, null],
  [null, null, null],
  [null, null, null],
];
```

...либо одномерного.

```ts
[null, null, null, null, null, null, null, null, null];
```

При завершении игры победой крестиков поле может иметь вид...

```ts
[
  ["x", "x", "x"],
  [null, "o", null],
  [null, "o", null],
];
```

либо

```ts
["x", "x", "x", null, "o", null, null, "o", null];
```

##### Состояние статуса

Возможные статусы игры:

`x-wins`, `o-wins`, `draw`, `x-move`, `o-move`

В начале игры имеет вид

```ts
"x-move";
```

...а при победе крестиков будет равен

```ts
"x-wins";
```

#### Локальное хранилище

Информация о незавершенной игре хранится по ключу `xo__game`: содержит информацию об очереди хода (`x` или `o`) в поле `move` и массив с состоянием игровой доски в поле `board`. По завершению игры (победой любого из игроков либо ничьей) или по ручному сбросу данные из `localStorage` очищаются.

Информация об именах игроков хранится по ключу `xo__players` и содержит данные игрока, играющего за крестики, по ключу `x`, и за нолики по ключу `o`. К данным относятся имя игрока и его цвет / эмодзи.

Для реализации взаимодействия с хранилищем (чтения, записи, удаления и проверки наличия ключей) используйте `Reducer API` либо `Context API`.
